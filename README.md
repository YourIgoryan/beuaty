# Beauty Salon Telegram Bot

Шаблон Telegram-бота для салона красоты/парикмахерской на Python, aiogram 3, FastAPI и SQLAlchemy. SaleBot не нужен.

## Что реализовано

- Клиентское меню: услуги и цены, запись, мои записи, контакты, мастера и портфолио.
- Запись: услуга → мастер или «любой свободный» → дата → время → номер телефона → подтверждение.
- Номер телефона можно передать через Telegram-кнопку контакта или ввести вручную; он сохраняется в базе и отправляется администратору с новой записью.
- Несколько демонстрационных мастеров с специализациями.
- Демонстрационное портфолио с изображениями; перед запуском замените их реальными фото салона в таблице `work_examples`.
- Проверка конфликтов по времени для каждого мастера; вариант «любой свободный» назначает конкретного свободного мастера.
- Отмена и просмотр будущих записей.
- Админ-панель по Telegram ID: записи на сегодня, список услуг и мастеров.
- Уведомления администраторам о новых записях и напоминания клиентам.
- FastAPI endpoints `/health`, `/api/services`, `/docs`.
- Один Render Web Service запускает и API, и Telegram polling; PostgreSQL рекомендуется для хостинга.

## Рекомендуемый запуск на Render

**Да, нужен GitHub:** Render подключается к репозиторию и автоматически собирает проект при push. Локальный компьютер после деплоя держать включённым не требуется.

### 1. Загрузите проект в GitHub

1. Создайте новый пустой репозиторий на GitHub, например `beauty-salon-bot`. Не добавляйте к нему README или другие файлы при создании.
2. Распакуйте архив и откройте PowerShell в папке `beauty_salon_bot`.
3. Выполните команды (замените `YOUR_GITHUB_NAME` на свой логин GitHub):

```powershell
git init
git add .
git commit -m "Initial beauty salon bot"
git branch -M main
git remote add origin https://github.com/YOUR_GITHUB_NAME/beauty-salon-bot.git
git push -u origin main
```

`.env` и локальные базы данных исключены через `.gitignore`. Не коммитьте токен бота.

### 2. Создайте PostgreSQL в Render

1. В Render откройте **New → PostgreSQL** и создайте базу данных.
2. Откройте её страницу и скопируйте **Internal Database URL**. Используйте внутренний адрес, если база и веб-сервис находятся в одном регионе Render.
3. Не публикуйте строку подключения: в ней содержатся учётные данные базы.

PostgreSQL нужен потому, что файловая SQLite-база на файловой системе обычного Render Web Service не подходит для постоянного хранения данных при повторных деплоях.

### 3. Создайте сервис из репозитория

1. В Render выберите **New → Blueprint** (или создайте Web Service из GitHub-репозитория).
2. Подключите репозиторий `beauty-salon-bot`. Render прочитает `render.yaml`.
3. В Environment добавьте значения:

| Переменная | Что указать |
|---|---|
| `BOT_TOKEN` | Токен от BotFather |
| `ADMIN_IDS` | Telegram ID администратора; несколько ID через запятую |
| `DATABASE_URL` | Internal Database URL созданной PostgreSQL |
| `SALON_NAME` | Название салона |
| `SALON_DESCRIPTION` | Короткое описание |
| `SALON_ADDRESS` | Адрес салона |
| `SALON_PHONE` | Телефон салона |
| `TIMEZONE` | Например `Europe/Moscow` |

4. Нажмите **Deploy** и дождитесь успешной сборки.
5. Откройте адрес сервиса Render + `/health`. Ожидаемый ответ: `{"status":"ok","service":"beauty-salon-bot"}`.
6. Откройте бота в Telegram и отправьте `/start`.

В `DATABASE_URL` вставляйте именно URL из Render, а не SQLite-пример из `.env.example`.

### 4. Важно про постоянную работу

Для круглосуточной работы используйте постоянно работающий Web Service (план без автоматического засыпания). Бесплатные Web Services Render могут засыпать после периода без входящих HTTP-запросов, из-за чего Telegram polling и напоминания не будут работать непрерывно. Health endpoint нужен для проверки состояния, но сам по себе не гарантирует отсутствие засыпания.

## Локальный запуск для разработки (не обязателен для Render)

Требуется Python 3.11 или 3.12.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Укажите `BOT_TOKEN` и `ADMIN_IDS` в `.env`, затем запустите:

```powershell
uvicorn app.server:app --host 0.0.0.0 --port 8000
```

Локальные адреса: `http://127.0.0.1:8000/health`, `http://127.0.0.1:8000/api/services`, `http://127.0.0.1:8000/docs`.

## Демонстрационные данные и настройка

При первом запуске создаются примерные услуги, три демонстрационных мастера и три демонстрационные записи портфолио. Имена, цены, длительность и фотографии нужно заменить на реальные данные салона. В этой версии список услуг и мастеров доступен в админ-панели для просмотра; полноценное добавление/редактирование этих данных кнопками ещё не реализовано.

Для каждого салона создавайте отдельного Telegram-бота, отдельный Render-сервис и отдельную базу данных. Не используйте один токен или базу для нескольких клиентов.
